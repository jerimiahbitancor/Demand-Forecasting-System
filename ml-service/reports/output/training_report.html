7. Predictions

Actual vs. predicted quantity over the held-out test period, for the same high- and low-volume products used in the split stage.

Note on what this does and doesn't show: every test row here uses lag_1/lag_7/rolling_7/rolling_14 computed from real, actual historical sales (that's what engineer_features() produced before the split ever happened) — this is one-step evaluation against real held-out data, not a simulated multi-day recursive forecast. A live forecast run (see forecast_service.generate_forecast()) instead feeds each day's own prediction back in as the next day's lag_1 when the real value isn't known yet, which compounds error the further out it recurses — that's the reason forecasts are capped at 7 days in production, and it's a different (harder) scenario than what this chart evaluates.
